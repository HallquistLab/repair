# REPAIR numerical reference fixtures

`repair-reference.rds` contains six synthetic inputs and expected results
produced independently of this R package. Metadata in the RDS records source
paths, hashes, source-repository commit, estimator settings, and R version.

The companion `blup_unshrinking` repository at commit
`b1f09f430d2214d5c4c8815b1386b62cb4ae159e` supplied:

- `R/fuller_mlm.R`: full M-MOM matrices and intermediate quantities;
- `R/stage2_estimators.R`: primary simulation coefficient, SE, and interval;
- `vig_hallquist_2026/analysis/fuller_algebra_audit_simulation.R`: independent
  algebra-audit coefficient, SE, and interval.

Cases cover predictor-only, outcome-only, both-sided, heteroskedastic, correlated
error, and weak-information inputs. The weak-information case distinguishes the
manuscript's modified covariance bread from the former unregularized bread.

Ordinary tests read the fixture without the sibling repository. Regeneration is
an intentional maintenance action using `dev/generate_repair_fixtures.R`; inspect
that script's usage and review any resulting fixture change. Do not regenerate
expected outputs from the package being tested.


## Observation-to-inference fixtures

`inst/extdata/nlme-workflow-reference.rds` contains three single-model nlme
reproduction cases, generated by `dev/generate_nlme_fixtures.R`.
`inst/extdata/multimodel-workflow-reference.rds` contains two dual-process cases,
generated by `dev/generate_multimodel_fixtures.R`: independent prediction errors and
supplied nonzero cross-model prediction-error covariance. Both generators additionally
use `R/blup_helpers.R` for production likelihood-only predictions. Each fixture records
source hashes and versions; neither generator loads the package being tested.

The multi-model cases preserve within-model intercept/slope covariance and test
both computation backends from raw repeated observations through coefficients,
SEs, covariance matrices, and intervals. The supplied cross-error case propagates
a known residual correlation of 0.25 with fitted marginal scales through the
score operators. Tests also verify the dual-process population predictor/outcome
SD ratio used for reporting. These synthetic per-dataset cases are not the
published Monte Carlo tables. See `dev/multimodel-validation.md` for the contract
and `vignettes/multiple-models.Rmd` for the executable public workflow.


## Posterior reliability references

`inst/extdata/reliability-reference.rds` is generated by
`dev/generate_reliability_fixtures.R` without loading repair. It refits the three
single-model nlme observation datasets and uses `R/reliability_calibration.R` in
the companion repository to compute posterior covariances, marginal reliability,
contrast reliability, and intercept-residualized slope reliability. The RDS
records source commit/hash, source-dataset fixture hash, R version, and nlme
version. Tests compare unit-specific values and equally weighted summaries.
These are plug-in posterior reliability references, not structural prediction-error
covariances or reliability confidence intervals. Existing numerical fixtures
remain unchanged.


## Nested nuisance references

`inst/extdata/nested-workflow-reference.rds` contains two synthetic lmer datasets
with 48 target people each. Cases cover day intercepts and multiple nuisance
groups including correlated day intercept/slope effects. They include prior
weights, offsets, unequal cluster sizes, shuffled observations, an excluded
response, and unused factor levels. Expectations include joint likelihood-only
predictions/covariance, within-unit nuisance covariance, target posterior covariance,
and structural coefficients/SEs/intervals/full covariance.

`dev/generate_nested_fixtures.R` never loads repair. It builds independent GLS
and posterior matrices directly from the fitted model quantities, then checks
Fuller M-MOM inference against the companion production code and algebra audit.
Source commit/hashes, generator hash, R/lme4 versions, and settings are embedded
in `provenance`. Refit comparisons use tolerance 1e-5 for optimizer/platform
variation; frozen expectations are never generated from repair. These are
per-dataset implementation references, not a coverage simulation.

## Step-up reference

`step-up-reference.rds` reuses the six independent structural-input cases above
and adds stricter two-stage selection and impossible-guard fallback cases.
`dev/generate_step_up_fixtures.R` obtains expectations from the separate research
`fit_fuller_dual_alpha_stepdown()` implementation with internal scaling disabled,
and confirms its selected-alpha results against its fixed-alpha core. The RDS
records the research source hash, revision, settings and R version. Neither the
generator nor normal tests obtain expected values from repair. These are
per-dataset algorithm comparisons, not coverage guarantees. Existing fixtures
are not changed.

`step-up-60c46ec.R` freezes the original package's M-MOM pipeline, conditional
SEs, guards and exhaustive search at commit
`60c46ece17071f7401717a2eefe1a169e5a598d6`. Tests source it into a separate
environment as an oracle for computation-only changes, resolving unchanged
shared input/covariance/solver helpers in the namespace. Never regenerate it
from the optimized implementation. Comparisons require identical selected
alphas, complete coefficient/SE/covariance outputs, failure decisions, and guard
checks at every evaluated point. Complete matched public bootstraps also check
draw maps, selected constants, attempt eligibility, RNG preservation and interval
extraction, excluding elapsed timings and unevaluated candidate histories.
